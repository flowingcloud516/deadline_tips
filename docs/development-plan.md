# Deadline Tips 开发计划

## 1. 技术方案

- 桌面运行时：Tauri 2
- 前端：React + TypeScript + Vite
- 样式：原生 CSS 与集中式设计变量，避免在第一版过早引入重型组件库
- 数据校验：Zod
- 日期计算：以 `YYYY-MM-DD` 字符串和本地日历算法为边界，避免日期时区漂移
- 单元测试：Vitest
- 原生能力：Rust 命令负责文件选择、JSON 原子读写、托盘、窗口与开机自启

## 2. 架构边界

```text
React UI
  -> application services
      -> task/domain rules
      -> StoragePort interface
          -> TauriJsonStorage adapter
          -> MemoryStorage adapter (tests/dev)
  -> Tauri window/tray commands
```

关键原则：

- 日期与周期规则放在无 UI、无 Tauri 依赖的领域模块中。
- 所有文件访问通过 `StoragePort`，为后续导入、导出和其他存储方式预留接口。
- 窗口状态、用户设置和任务数据使用明确的数据模型与版本迁移。
- 设计变量和图标资源独立管理，方便用户审阅和替换。

## 3. 面向并行开发的模块划分

工程按稳定接口拆分，使多个开发任务可以在不同文件范围内并行推进：

| 模块 | 主要职责 | 允许依赖 | 并行边界 |
| --- | --- | --- | --- |
| `domain` | 任务模型、重要属性、状态、周期和日期计算 | 无 UI、无 Tauri | 可独立开发与测试 |
| `application` | 新增/编辑/完成任务、重要性优先的任务分区查询 | `domain`、存储端口 | 可使用内存适配器并行开发 |
| `storage-contract` | JSON schema、版本迁移、存储接口 | `domain` 类型 | 先冻结契约，供前后端共同使用 |
| `storage-tauri` | Rust 原子读写、路径选择与迁移 | 存储契约、Tauri | 与 UI 并行开发 |
| `widget-ui` | 近期区、重要区、响应式字体 | application 查询接口 | 使用 fixtures/mock 并行开发 |
| `manager-ui` | 表格、表单、筛选、状态与重要性编辑 | application 命令接口 | 与悬浮窗并行开发 |
| `desktop-shell` | 多窗口、托盘、置顶、自启动 | Tauri、窗口消息契约 | 与业务模块并行开发 |
| `design-system` | tokens、图标和视觉资源 | 无业务依赖 | 经用户确认后独立迭代 |
| `platform-validation` | Win10/Win11 清单、打包与兼容修复 | 完整构建 | 后期并行执行验证场景 |

并行协作规则：

- 每个模块设置公开类型与端口文件；并行工作优先修改模块内部，不跨边界直接访问实现细节。
- 领域模型与存储 schema 的变更先更新契约和测试，再通知所有消费模块。
- UI 使用固定 fixtures 和内存存储开发，不等待 Rust 文件存储完成。
- 每个并行分支必须通过自身测试、类型检查，并在合并前运行全量测试。
- 避免多人同时修改入口文件；窗口注册、路由和依赖装配集中在集成阶段处理。

- 重要任务属性，以及近期/重要任务的独立查询规则。

### 阶段 B：可确认的视觉原型

确认点：悬浮窗视觉方向已由用户确认，进入完整交互实现；管理面板和托盘图标随功能实现继续审阅。

### 阶段 C：任务管理

### 阶段 D：JSON 持久化与设置

### 阶段 E：桌面集成

完成条件：Windows 10 与 Windows 11 验收清单均完成；未解决问题具有明确影响和处理计划。

## 5. 初始任务拆分

1. 初始化 Vite/React/Tauri 配置。
2. 建立类型、重要属性、校验器、日期算法和测试。
3. 建立存储接口及内存实现。
4. 制作包含近期/重要双区域的可审阅悬浮窗，以及管理面板原型。
5. 用户确认视觉方向。
6. 实现任务管理交互。
7. 实现 Rust JSON 存储命令和路径选择。
8. 实现悬浮窗与窗口状态持久化。
9. 实现托盘和开机自启。
10. 执行 Windows 10 测试、修复并打包。
11. 转移到 Windows 11，执行兼容性验证、修复与 Windows 10 回归。

## 6. 工具链与环境

开发机需要：

- Node.js 与 npm。
- Rust stable 与 Cargo。
- Microsoft C++ Build Tools（Desktop development with C++）。
- Windows 10 SDK。
- WebView2 Runtime；较新的 Windows 10 通常已安装，否则需补装。

当前 Windows 10 环境已验证 Node.js、npm、Rust/Cargo、C++ Build Tools、Windows 10 SDK 和 WebView2；前端测试、生产构建和 Tauri Rust 编译检查均通过。PowerShell 下使用 `npm.cmd`。

## 7. 开发模型与代理策略

- 并行子任务优先请求 `gpt-5.6-luna`，适用于测试补全、独立模块实现、文档同步等边界清晰的高吞吐工作。
- 当前 Codex 会话若未开放 Luna 调度能力，必须明确记录限制；暂用 `gpt-5.6-terra` 执行同类任务，不得声称使用了 Luna。
- 复杂架构决策、跨模块集成、疑难 Windows 原生问题和最终审查可使用 `gpt-5.6-sol`。
- 无论模型如何分配，主任务负责冻结接口、检查共享工作区冲突、运行全量验证并整合结果。
- 用户未要求并行时仍按模块边界开发；需要启动并行代理时遵守当前 Codex 会话的代理权限和可用模型列表。

## 8. 测试策略

- 单元测试：任务校验、截止日期排序、逾期派生、所有重复日期计算。
- 边界测试：闰年与非闰年 2 月、大小月、31 日规则、跨年、月末前 0/n 天。
- 存储测试：首次启动、正常读写、损坏 JSON、无权限路径、迁移中断。
- 组件测试：表单校验、状态操作、筛选和排序。
- 查询测试：近期范围、重要性优先分区、跨区去重、重要任务临期/逾期高亮、完成/跳过后的区域移除。
- Windows 10/11 手工测试：窗口缩放、DPI 缩放、多显示器、托盘、关闭隐藏、自启动。
- 移植测试：干净检出后安装依赖与构建、跨系统复制 JSON、非固定盘符及不同用户名路径。

## 9. 主要风险

- Tauri 工具链未安装会阻塞原生集成与打包。
- Windows 不同 DPI 和多显示器可能影响悬浮窗字体与位置恢复，需要真机验证。
- 用户选择的 JSON 路径可能位于不可写、移动或同步目录，需要明确错误处理和回退。
- 周期任务若未来加入历史记录，需要保持当前 schema 可迁移，避免直接改变现有字段语义。
- 并行开发若绕过端口直接引用实现，会导致高冲突与难以测试；接口冻结和集成所有权必须执行。
- Windows 10 首调通过不能替代 Windows 11 验证，尤其需要关注 DPI、托盘与自启动行为差异。
- Luna 虽为官方 GPT-5.6 型号，但具体 Codex 会话可能不提供代理调度入口，计划需要允许透明降级而不阻塞工程。
