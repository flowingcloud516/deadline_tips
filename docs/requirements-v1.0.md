# Deadline Tips 需求规格说明书

版本：1.0（基于 `requirement_v0.1.md` 梳理）  
目标平台：Windows 10、Windows 11  
首要调试平台：Windows 10

## 1. 产品目标

Deadline Tips 是一个本地运行、常驻桌面的截止日期管理工具。它通过可调整大小的桌面悬浮窗展示近期任务及剩余天数，并提供独立的任务管理面板维护任务。

第一版强调轻量、直观和离线可用，不包含账户、联网同步及系统通知。

## 2. 用户与使用场景

主要用户为需要持续关注多个一次性或重复截止日期的个人用户。

典型场景：

1. 用户创建一次性任务并指定截止日期。
2. 用户创建每周或每月重复任务。
3. 用户在桌面悬浮窗中查看未来一段时间内的任务。
4. 用户完成、跳过或调整某一期周期任务，然后生成或编辑下一期。
5. 用户通过系统托盘打开管理面板、显示或隐藏悬浮窗、退出程序。

## 3. 功能范围

### 3.1 任务字段

每项任务包含：

| 字段 | 规则 |
| --- | --- |
| ID | 系统生成且保持稳定，不向用户开放编辑 |
| 任务名 | 必填，最多 20 个字符；字符按 Unicode 字符计数 |
| 任务详情 | 可选，仅纯文本，不限制业务长度；实现应设置合理文件与输入保护 |
| 任务类型 | 一次性、每周、每月 |
| 截止日期 / 结束日期 | 必填，本地日期，不包含时分秒；一次性任务表示截止日期，周期任务表示整体结束日期 |
| 重要任务 | 用户可编辑的布尔属性；与任务类型、周期规则相互独立 |
| 状态 | 待完成、已完成、已跳过；逾期由日期和状态动态计算 |
| 重复规则 | 周期任务必填，一次性任务为空 |
| 创建时间 | 系统记录 |
| 更新时间 | 系统记录 |

### 3.2 一次性任务

- 用户直接选择截止日期。
- 用户可编辑任务的全部业务字段。
- 标记完成后，任务保留在数据中，但不再显示在默认的近期任务列表。

### 3.3 每周任务

- 用户选择星期一至星期日中的一天。
- 用户可编辑当前状态和整体结束日期。
- 下一次发生日期根据本机今天、重复规则和整体结束日期动态计算，不持久化且不得晚于结束日期。
- “完成本期”后保持整体结束日期不变，并继续根据重复规则动态计算下一次发生日期。
- 到期但未完成时保持当前期并显示逾期，不自动滚动到下一期。

### 3.4 每月任务

支持两种规则：

1. 每月固定日期：1 至 31 日。如果目标月份没有该日期，则使用该月最后一天。例如每月 31 日在 4 月落到 4 月 30 日。
2. 月末前 n 天：按日历日计算。月末当天为 0 天前，月末前一天为 1 天前。计算必须使用目标年份的实际月份天数，并正确处理闰年 2 月 29 日。

周期任务的完成、逾期和手工编辑规则与每周任务一致。

周期任务在悬浮窗中同时显示下一次发生日期及其剩余天数，以及距离整体结束日期的剩余天数。若结束日期前不再有符合规则的发生日期，应明确显示“截止前没有下一次任务”。

### 3.5 状态与逾期

- 用户可以直接编辑任务状态。
- 当状态为“待完成”且下一截止日期早于本机当天日期时，界面显示“已逾期”。
- “已逾期”是派生显示状态，不覆盖持久化的待完成状态。
- 周期任务支持“完成本期”。该操作先记录本期完成，再计算下一截止日期并恢复为待完成。
- 第一版不要求保存完整的历史执行记录；数据结构应允许后续增加历史记录。

### 3.6 桌面悬浮窗

- 无边框、小尺寸、可拖动。
- 支持调整窗口大小，并保存最后一次位置和尺寸。
- 可设置是否置顶，默认置顶。
- 内容固定分为“近期即将到期”“周期任务”和“重要任务”三个区域。
- “近期即将到期”显示设定范围内的待完成和逾期一次性任务，默认范围为未来 7 天。
- “周期任务”显示所有非重要且待完成的周期任务，不受近期范围限制。
- 范围可选 3、7、14、30 天。
- “重要任务”显示所有标记为重要且状态为待完成的任务，不受近期范围或长期时间上限限制。
- 重要属性具有分区优先级：重要任务即使是周期任务、进入近期范围或已经逾期，也只显示在“重要任务”区域，不进入其他区域。
- 重要任务临期或逾期时，在“重要任务”区域内使用红色等显著方式高亮。
- 近期任务每项至少显示任务名、截止日期、剩余天数或逾期天数。
- 重要任务每项至少显示任务名、截止日期、剩余天数和约剩余周数；不足一周时仍明确显示天数。
- 三个区域各自按截止日期升序排列；逾期任务优先。
- 重要任务的长期展示范围不设季度或半年硬上限，使用户可自行标记更长期目标。
- 窗口缩放时，布局与字体同步响应：字体依据窗口尺寸在可读的最小值和最大值之间平滑调整，内容超出时允许滚动。
- 每个区域分别提供空状态；窗口较小时允许区域折叠或滚动，但不得隐藏逾期提示。

### 3.7 任务管理面板

- 使用表格化布局完整呈现任务字段。
- 支持新增、查看、编辑和删除任务。
- 支持按状态、类型筛选，并按截止日期排序。
- 支持编辑“重要任务”属性，并按重要性筛选。
- 编辑时进行字段校验，并给出中文错误提示。
- 删除前要求用户确认。
- 支持打开数据与显示设置。

### 3.8 系统托盘

- 程序启动后创建托盘图标。
- 悬浮窗和任务管理窗口均不显示任务栏按钮，窗口入口统一由悬浮窗和系统托盘提供。
- 托盘菜单至少包含：显示/隐藏悬浮窗、打开任务管理、设置、退出。
- 点击窗口关闭按钮时隐藏到托盘，不退出进程。
- 仅通过托盘“退出”或管理面板内明确的退出操作结束程序。
- 提供开机自启动开关，默认关闭。

### 3.9 数据存储

- 第一版使用本地 JSON 文件。
- 用户可选择数据文件的存储路径。
- 默认路径使用 Windows 用户应用数据目录，不写入程序安装目录。
- 路径更改时应校验目标目录可写，并安全迁移现有数据；迁移失败时保留原文件。
- 写入采用临时文件加原子替换策略，降低异常退出造成文件损坏的风险。
- JSON 顶层包含 `schemaVersion`，便于后续迁移。
- 存储功能通过独立接口访问，界面与业务逻辑不得直接读写文件。
- 第一版不提供可见的导入/导出按钮，但存储接口需为后续导入、导出、备份和其他存储实现预留扩展点。

建议数据顶层结构：

```json
{
  "schemaVersion": 1,
  "tasks": [],
  "settings": {},
  "history": []
}
```

### 3.10 设置

- 近期任务范围：3、7、14、30 天，默认 7 天。
- 悬浮窗置顶：默认开启。
- 开机自启动：默认关闭。
- 数据文件路径：显示当前路径并允许修改。
- 界面主题参数应集中管理，第一版至少支持清晰的浅色主题。

## 4. 视觉与资源要求

- 悬浮窗视觉方向已经用户确认；管理面板和托盘图标仍需在对应功能实现后审阅。
- 配色、圆角、间距、阴影、字体尺度等使用集中式设计变量，避免散落在组件中。
- 图标以独立源文件和导出资源保存，不嵌入业务代码，方便替换。
- Windows 应用图标应保留可编辑源稿，并导出 Tauri 所需尺寸。
- 已确认的悬浮窗视觉可进入功能实现；设计变量与源文件仍须保持可调整。
- 默认使用 Windows 可用的中文系统字体回退链，不强制下载网络字体。

## 5. 非功能要求

- 支持 Windows 10 和 Windows 11 的 64 位环境；开发阶段以 Windows 10 为首要调试环境，随后必须在 Windows 11 上执行移植验证和兼容性修复。
- 不依赖固定盘符、开发机用户名、绝对路径或仅 Windows 10 存在的系统行为。
- 构建、安装和数据目录必须通过 Windows/Tauri 提供的系统路径解析，不把开发机路径写入发布产物。
- JSON 数据格式、设置格式与路径迁移逻辑必须在 Windows 10/11 间保持一致，支持复制数据文件后继续使用。
- Windows 11 验证至少覆盖安装/卸载、WebView2、托盘、窗口置顶与缩放、多 DPI、开机自启、数据路径选择和中文显示。
- 使用 Tauri、React 和 TypeScript。
- 日常空闲时保持较低资源占用；具体基线在首个可运行构建后测量。
- 任务日期运算以本机日历日期为准，避免 UTC 转换导致日期偏移。
- 悬浮窗和管理窗口在每个本地整点刷新当前日期，并在窗口重新获得焦点或恢复可见时立即刷新，确保跨午夜后的剩余天数自动更新。
- JSON 解析、路径变更和文件写入错误必须可恢复并向用户说明。
- 核心日期计算和数据迁移需要自动化测试。
- 第一版所有用户界面文本使用简体中文。

## 6. 第一版明确不包含

- 系统通知或声音提醒。
- 用户登录、云端同步和多设备同步。
- 季度、年度或自定义复杂重复规则。
- 富文本、附件和协作功能。
- 完整任务执行历史界面。
- 面向 macOS、Linux 或移动端的支持。

## 7. 第一版验收标准

1. 在 Windows 10 上能够安装、启动、隐藏到托盘并正常退出。
2. 用户能创建、编辑、删除一次性、每周和每月任务。
3. 固定日期、月末前 n 天及闰年 2 月日期计算通过测试。
4. 逾期任务保持逾期，直到用户编辑状态或完成本期。
5. 悬浮窗可以拖动、调整大小并恢复位置尺寸，字体随尺寸合理变化。
6. 管理面板能完整显示任务字段并完成筛选、排序和编辑。
7. 数据在应用重启后保持；用户可以修改 JSON 路径并安全迁移数据。
8. 关闭窗口不会结束进程，托盘可以重新打开窗口。
9. 未启用任何系统通知或联网功能。
10. 视觉方案和应用图标经过用户确认后再标记第一版完成。
11. 重要任务可以人工标记、取消标记，并在独立区域显示剩余天数和约剩余周数。
12. 重要任务无论是否临期或逾期都只在重要区域出现；临期或逾期时显著高亮，不产生双区域重复。
13. Windows 11 移植验证清单执行完毕，发现的兼容问题完成修复或明确记录。

## 8. 已确认决策

- 仅支持 Windows 10/11，优先在 Windows 10 调试。
- 桌面展示器采用可缩放的悬浮窗，字体随界面调整。
- 第一版无系统通知。
- 周期任务逾期后不自动进入下一期，状态允许用户编辑。
- 月末规则按日历日计算并覆盖闰年。
- 本地 JSON 存储，路径可配置，预留导入导出接口。
- 关闭时最小化到托盘，支持可选开机自启。
- 技术栈采用 Tauri + React + TypeScript。
- 悬浮窗包含近期任务区与重要任务区；重要属性由用户编辑，且独立于一次性/周期性类型。

## 9. 补充确认的展示规则

- 重要任务始终只在重要区域显示；进入近期范围或逾期时在重要区域内以红色等显著方式高亮。
- “约剩余周数”按剩余天数除以 7 展示到一位小数；同时始终保留精确剩余天数。
- 已完成或已跳过的重要任务不显示在悬浮窗重要任务区，但仍保留在管理面板中。
